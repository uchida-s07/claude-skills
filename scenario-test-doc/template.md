# シナリオテスト仕様書: {プロジェクト・機能名}

> Vモデル: システムテスト（右側）/ 対応する設計: ② 要件定義
> ①〜⑤の設計書が固まった段階で、② の受入基準をもとに生成する。
> 実施者は **Build した実アプリ** に対して手動でシナリオを実行し、判定を記録する。

## 使い方（実施者向け）

1. Build した実アプリを起動する（下記「前提環境」を満たす）
2. シナリオを上から順に実行し、各ステップの期待結果と一致するか確認する
3. 判定欄に ☐Pass / ☐Fail を記録する（Fail はメモに事象を残す）
4. Fail は原因を **要件(②)・設計(③〜⑤)・実装(Build)** のどこかに切り分けて修正する
5. 全シナリオ Pass ＝ 要件を満たしたことの証明

## 3. 判定の切り分けガイド（Fail時）

| Fail の症状 | 疑う層 | 確認先 |
| ---------- | ----- | ----- |
| 受入基準の期待結果が仕様と食い違う | 要件(②)の誤り | 02-requirement の該当受入基準 |
| 画面表示・エラー文言が想定と違う | 基本設計(③) | 03-spec / mocks/mockup.html |
| データの保存先・保存内容がずれる | 詳細設計(④) | 04-db |
| インターフェースの入出力・エラーがずれる | 詳細設計(⑤) | 05-api-ipo |
| 上記が正しいのに動かない | 実装(Build)バグ | Build 成果物 |
